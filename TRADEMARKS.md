# Trademarks, naming, and official status

## Public-facing qualifier

The project uses **Witness Evidence** as its public-facing qualifier and the category **Open Evidence Layer for Agentic Systems**.

“Evidence & Learning Infrastructure for Multi-Agent Systems” is north-star language only; it does not describe shipped learning behavior in `v0.1.0`.

This is a documentation and anti-confusion measure, not a technical rename. The following identifiers remain unchanged:

- repository `MaximilianoColoma/witness`;
- package `witness-public`;
- Python module `witness_public`;
- released `v0.1.0` tag and artifacts;
- MCP tool names and versioned contracts.

Compatibility statements should use the technical identifier and tested version. Public prose may use “Witness Evidence” or “Witness” where the project context is unambiguous.

## Unrelated Witness project

An established, unrelated open-source project is published at [in-toto/witness](https://github.com/in-toto/witness) and describes itself as software supply-chain provenance and risk-management tooling.

This repository is **not affiliated with, endorsed by, or a distribution of** the in-toto Witness project. Witness Evidence addresses identity-bound decisions, outcomes, evidence references, acceptance state, and bounded context for agentic systems.

Contributors should not use `witness.dev`, in-toto project artwork, or language that could imply common ownership or compatibility. Search results, package registries, domains, organization names, and prospective marks must be checked again before any future repository, package, organization, or domain rename.

**No legal conclusion** about trademark ownership, registrability, infringement, or geographic rights is made here. A material naming change requires a separate owner decision and, where warranted, qualified legal review.

## License and official status

The Apache License 2.0 licenses the code but does not grant permission to use the names, logos, trade names, service marks, or product identity of the official project except for reasonable attribution and description of origin.

Forks are welcome under Apache-2.0, but a fork must rename the product and must not imply endorsement, certification, security support, compatibility approval, or official release status unless Maximiliano Coloma-Seegers grants written permission.

Accurate statements such as “derived from Witness Evidence” are allowed when they are not misleading. Use of an official name solely to describe protocol compatibility must identify the tested version and must not imply certification.
